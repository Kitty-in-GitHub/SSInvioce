# 开发计划与进度

> 最近更新：2026-10-28
> 详细流程见 [材料上传与识别流程.md](材料上传与识别流程.md)。

---

## 1. 项目定位

学生社团报销材料（发票 PDF、订单截图、支付记录）的收集、齐套检查、自动归类与 A4 拼版导出工具。
本机单用户 Web 应用：后端只监听 `127.0.0.1:8765`，数据全部落在项目 `data/`。

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 后端 | FastAPI + SQLite + PyMuPDF + RapidOCR(onnxruntime) |
| 前端 | Vue 3 + Vite（无 UI 框架） |
| 文档生成 | python-docx / docxtpl + Word / WPS / LibreOffice 转 PDF |
| 部署 | 本机运行；`build-green.bat` 打 Windows 绿色包 |

## 3. 开发方向

1. **材料链路**：上传 → 收件箱 → 自动识别/聚类 → 确认成条目；任何时候可中断、可恢复。
2. **导出链路**：齐套校验 → A4 拼版（单条 / 批量 / 按组）→ 可前置公文表。
3. **数据安全**：判重、回收站、备份恢复。
4. **可维护性**：隔离环境自检脚本 + 文档，让改动能被回归验证。

## 4. 已完成

### 4.1 基础工作台
- 条目 CRUD、分组、金额（自动 / 手改 / 强制重识别）、齐套状态
- 材料槽位上传（PDF / 图片）、替换语义、预览
- 收件箱：改类型、挂到条目、删除
- 设置：槽位与分类关键词、拼版画板、表格模板

### 4.2 材料上传与归类
- 单文件上传：立即挂条目 + 后台识别（金额 / 商家 / 日期 / 发票号 / 查重）
- 批量上传：文件直接落收件箱（数据库持久化），关窗、重启都不丢
- 聚类成拟建条目：按金额分桶 + 必填槽位贪心 + 商家/订单号/日期补簇
- 拟建条目「并入已有条目」：只补缺失槽位，不覆盖已有金额，槽位冲突拒绝
- 改类型立即持久化，关窗重开不丢
- 同批重复自动折叠为「重复副本」，确认入库时可按勾选丢弃
- 判重：发票号码 + **全类型**文件哈希（含历史缺号发票的哈希兜底）
- 电子发票号码提取回退：处理"号码与开票日期粘连"的新版版式

### 4.3 拼版导出
- A4 纵向拼版：发票在上，订单 / 支付等高并排；版式可拖拽
- 单条、多选批量、按分组导出；分组可前置填好的表格 PDF
- 表格 PDF 磁盘缓存，内容未变不重复转换
- 修复：电子发票红色监制章（`/Stamp` 注释）导出丢失；裁切框并入注释矩形

### 4.4 数据安全
- 回收站：批量丢弃 / 删材料 / 删条目都会移入 `data/trash/`，保留 30 天
- 恢复：原条目还在且槽位空闲 → 回原条目，否则回收到收件箱
- 备份 / 恢复（zip）
- 注意：上传替换仍直接删除旧文件，未进回收站

### 4.5 工程质量
- `scripts/check_invoice_seal.py`：印章保留自检（`--legacy` 可反证脚本有效）
- `scripts/check_inbox_staging.py`：隔离环境集成测试（当前 61 项断言，不碰真实 `data/`）
- 流程文档 `docs/材料上传与识别流程.md`

## 6. 已知限制

- 判重目前只能做到"同内容 / 同发票号"；重新下载、重新截图需要 L3 / L5。
- 「批量整理」会纳入收件箱里全部未归类材料。
- PDF 只读前 2 页文本且不做 OCR；扫描件金额只能靠文件名兜底。
- 批量确认里把**散件**挂到已有条目，不检查同槽冲突（拟建条目并入会检查）。
- 从回收站恢复后材料 id 会变（重新插入）。
- 集成测试依赖 `data/uploads` 下至少 4 份发票样本。

## 9. 工程约定

- 数据库不引入迁移框架：`init_db()` 里 `CREATE TABLE IF NOT EXISTS` + `_ensure_column()` 增量加列。
- 删除文件一律先走回收站（上传替换除外）。
- 改拼版 / 归类逻辑后跑第 7 节脚本；改前端后跑 `npm run build`。
- `data/`、`frontend/dist/` 不进版本库。
